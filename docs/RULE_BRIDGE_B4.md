# Milestone B4 — Structured hypothesis → candidate rule bridge

## Purpose

This is a **minimal, offline** source-independent bridge to the B3 verifier.
It does not turn English LLM expressions into Python, invent constants,
verify documentary evidence, certify constraint correctness or run an LLM.

All example ASTs in `data/rules/b4_example_proposals.json` are **hand-authored
fixtures**. Do not describe them as structured output generated by Luna/Sol.
Existing `luna_hypothesis_{finance,healthcare}.json` files contain free-text
expressions; B4 deliberately reports them as **blocked**, not auto-parsed.

## Research workflow

1. Provide permitted column names from the retained dataset metadata.
2. A future Luna/Sol call proposes **typed JSON ASTs** in the restricted B4 format.
3. B4 rejects unknown columns/operators/free-text and requires **named** values
   for every numeric constant, tolerance, condition and rounding parameter.
4. The local, curator-supplied parameter registry supplies candidate values and
   records provenance. The registry **does not check its cited documents**.
5. Compile to B3 format and run `src.generic_verifier.validate_rule`.
6. Status remains `candidate_executable_unverified` until a separate independent
   ground-truth/evidence adjudication. Missing values cause `blocked_unresolved`.

The healthcare rounding entry is labelled `empirical_same_dataset`: it was
selected using the entire original GLU_J snapshot. It is **not independent
held-out evidence**. Manufacturing and cyber registrations are fixture-only.

## Notes on compatibility

- B4 targets the existing `src/generic_verifier.py` DSL v0.1, **not** the
  separate legacy `data/rule.schema.json`. Both must remain distinguishable.
- Typed AST is a contract for **future** model requests, not a claim that
  prior free-text Luna outputs were automatically parsed.
- B3 `context_keys` requires trusted per-field provenance populated by a
  future ingestion adapter. B4 neither invents this context nor checks it.
- Numeric registry values can be labelled documented, empirical or fixture;
  in every case compiled candidates remain **unverified**.
- Domain independence of the compiler/verifier is not domain-independent
  discovery or four-domain empirical validation.
